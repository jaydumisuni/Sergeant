# Sergeant Assurance Evolution Through SAE-100 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Advance the frozen Sergeant Assurance Evolution roadmap from the current PROVEN foundation through `SAE-100 — Cpl / Officers / Judge / Sergeant Integration` without activating Genesis or weakening existing Sergeant authority.

**Architecture:** Extend the already-PROVEN Review World/RAB (`SAE-10`), ACR (`SAE-20`), and Assurance Ledger (`SAE-40`) instead of introducing parallel authority models. Python owns orchestration, registries, closure, semantic qualification, proof-world and falsification composition; Rust is independently implemented in dependency-free crates for authority identity (`SAE-R1`) and constitutional admissibility (`SAE-R2`). Every roadmap node is built as an immutable CANDIDATE, exact-head proved and hostile-reviewed, guarded-merged, then closed by a separate PROVEN lifecycle generation before downstream proof consumes it.

**Tech Stack:** Python 3.11/3.12, pytest, existing `main_review` package, Rust stable/std-only crates, GitHub Actions, existing Main Review/Review Intelligence/Multiplatform proof workflows.

**Spec:** `docs/59-sergeant-assurance-evolution-roadmap.md` plus `docs/58-sergeant-assurance-evolution-founding-architecture.md`.

## Global Constraints

- Preserve `PASS / NEEDS WORK / BLOCK`, Sergeant/Cpl/officer/Judge hierarchy, model-free CPU path, security/default-deny, and no automatic merge/promotion.
- Preserve `UNKNOWN`/`PARTIAL`; unsupported or resource-exhausted paths fail closed to `UNKNOWN`/inadmissible rather than weaker PASS.
- Candidate code never self-qualifies, self-activates, issues qualification authority, or changes normal Sergeant verdict authority.
- Owner business-risk acceptance remains disjoint from engineering verdict/evidence.
- External review provenance and independence are explicit; project-controlled AI review is never relabeled `INDEPENDENT`.
- Rust and Python may share frozen specifications/vectors, never implementation code.
- No partial Assurance Evolution generation activates before `SAE-170` Genesis Exit.
- Each candidate and closeout merge must use exact-head reconciliation and existing guarded merge practice.
- PR #167 remains fenced under its original pre-Assurance-Evolution authority.
